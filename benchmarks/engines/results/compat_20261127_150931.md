## Notes (linux-5090, hand-written; the table above is generated)

Run on linux-5090 (Ryzen Threadripper 9960X pinned to 8 CPUs with `taskset -c 40-47`,
RTX 5090 for Lc0 and Maia-3), `SCAN64_ENGINE_POOL_BATCH_CONCURRENCY=2`, profiles in
`config/engines/compat/linux/`, engines as listed in `~/.local/opt/engines/MANIFEST.md`.

- **Rodent V ignores `go nodes N`**: it keeps searching until `stop`. Node-only
  searches (fast pass, focused pass, lesson verification) have no wall-clock limit, so
  `game_analysis` hung. A watchdog outside Scan64 killed the engine after 240 s
  (exit code -15). `lesson_verification` then failed with "engine process dead":
  the batch pool kept the killed process and did not start a new one. Hints and the
  Analysis Board work because the hint search has a time limit and a deadline.
- **Arasan 26.1 ignores `go nodes N`** too, but in the other direction: it stops
  after about 6k nodes (depth ~6) for any N. Every node-budget feature "works", at
  far less search than the budget: the 1M-node focused pass took 0.03 s.
- **Maia-3** answers from one policy pass and ignores node limits (focused pass 0.06 s).
- **Lc0** `node_scale` comes from measured nodes/second against Stockfish 18 (1 thread,
  ~850k nps on kiwipete): T1 ~100k nps with 2 search threads gives 0.12, BT4 ~11k nps
  gives 0.013.
- **Stockfish 11** is an extra row, not in the #397 list (an older Stockfish, classical eval).
